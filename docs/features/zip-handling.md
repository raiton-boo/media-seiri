# 機能: ZIP の取り込み(zip-handling)

## 1. 目的

ZIP の中にある写真・動画・RAW も、通常のファイルと同じように整理する。ZIP は数が多くない前提で、限定的な機能として扱う。利用者が先に展開する必要はない。

## 2. 関連する要件

[ZIP 内のファイル](../requirements.md#t-03)、[ZIP の入れ子](../requirements.md#t-04)、[サイドカー](../requirements.md#t-05)、[日付の代替の取得元](../requirements.md#d-02)、[ピン表示](../requirements.md#g-01)、[破損の検出](../requirements.md#r-01)
仕様書: §10-1 / フロー: `flows.md` 3章

## 3. 基本方針

- ZIP 全体を展開せず、中の**1ファイルずつ**を一時領域(`data/.../tmp/`)に取り出して処理し、すぐ削除する。
  - 必要な空きは、ZIP 内の最大の1ファイル分だけ。
- 元の ZIP は、変更しない ([コピー専用](../requirements.md#c-03))。
- ZIP 内のフォルダは、何層でもたどる。
- ZIP の中の ZIP(入れ子)は、深さ3まで開く。4段目以降は、開かず、警告として記録する ([ZIP の入れ子](../requirements.md#t-04))。

## 4. 処理の流れ

1. ソースのスキャンで、ZIP を検出する。
0. ZIP の中に、同じ名前のファイルが複数あるとき(名前の正規化で重なる場合も)は、2 つ目から `名前 (2).拡張子` のように連番を付けて、すべて取り込む(`ZIP_DUPLICATE_ENTRY` を警告として記録)。台帳は、同じ実行の中の、同じパスを、1 件しか持てないため。
2. 入れ子の深さを確認する(3 を超えたら、`ZIP_DEPTH_EXCEEDED` を警告として記録して、開かない)。
3. 開けるかを確認する(暗号化 → `ZIP_ENCRYPTED`、壊れている → `READ_FAILED`)。
4. 中身の一覧を取得し、ファイル名の文字コードを判定する。
5. エントリごとに、パスの安全性を検査し、種別に応じて処理する。
   - 写真・動画・RAW: 一時領域に取り出して、`ingest.md` の1ファイルあたりの処理を行い、すぐ削除する。
   - ZIP: 深さ+1 で、再帰する。
   - Takeout の `.json`: 日付と GPS の取得元として読む(コピーしない)。
   - その他: 対象外として件数を記録する。

## 5. 安全対策

| 項目             | 内容                                                                                |
| :--------------- | :---------------------------------------------------------------------------------- |
| パスの検査       | 展開先の外に出るパス(`../` や絶対パス)は、無視して、`ZIP_UNSAFE_PATH` を記録する    |
| 展開サイズの上限 | 1ファイルの展開サイズに上限(設定可能)を設け、異常に大きいものは、エラーにする。(仮) |
| 展開の圧縮率     | 圧縮率が異常に高いもの(ZIP 爆弾)は、上限で止まる                                    |
| 暗号化           | 開けないため、`ZIP_ENCRYPTED` を記録して、スキップする                              |

## 6. 文字コード

- ZIP 内のファイル名が、cp932(Shift_JIS)で保存されていることがある。文字化けを防ぐため、UTF-8 の指定がない場合は、自動判定して変換する。
- 判定が曖昧な場合は、cp932 を優先する。(仮)
- 変換後のファイル名は、NFC に統一する。

## 7. 元の場所の記録

`ソース/path/to/a.zip!/inner/b.jpg` の形で記録する(入れ子の場合は、`a.zip!/b.zip!/c.jpg`)。

- 重複比較(`dedupe.md`)や、エラー一覧に、この形で表示する。

## 8. Google Takeout の `.json` (要件: [サイドカー](../requirements.md#t-05))

Google フォトの Takeout で書き出した ZIP には、写真ごとに `.json` が付く。本体に日付・GPS がなく、`.json` にだけあることが多い。

### 8-1. 対応するファイル(仮)

| 写真                           | json                                                                  |
| :----------------------------- | :-------------------------------------------------------------------- |
| `IMG_1234.jpg`                 | `IMG_1234.jpg.json`(または `IMG_1234.jpg.supplemental-metadata.json`) |
| `IMG_1234(1).jpg`              | `IMG_1234.jpg(1).json`                                                |
| 編集済み `IMG_1234-edited.jpg` | 元の `IMG_1234.jpg.json`                                              |
| 長い名前(切り詰められる)       | 先頭の一致で、対応づける                                              |

- json の形式(ファイル名の付け方)は、Takeout の版によって違うため、複数の形に対応する。(仮)
- 写真と同じフォルダ(ZIP 内)にある json を、対応づける。

### 8-2. 読み取る項目

| 項目                               | 使い道                                                            |
| :--------------------------------- | :---------------------------------------------------------------- |
| `photoTakenTime`(UTC のエポック秒) | 日付の取得元(フォールバック `json`)。本機のタイムゾーンへ変換する |
| `geoData`(緯度・経度・高度)        | 本体に GPS がない場合の GPS。(0, 0) は、無効                      |

- 本体のメタデータが優先。json は、本体に日付・GPS がないときだけ使う ([日付の代替の取得元](../requirements.md#d-02))。
- json 自体は、コピーしない。

## 9. エッジケース

| 状況                                   | 振る舞い                                                 |
| :------------------------------------- | :------------------------------------------------------- |
| ZIP が壊れている(途中まで読める)       | 読めたエントリまでを処理し、以降は、エラーとして記録する |
| 同じ名前のエントリが、ZIP に複数ある   | 別のエントリとして、すべて処理する                       |
| ZIP 内に、写真がない                   | 件数を記録するだけ                                       |
| 一時領域が、いっぱいになる             | `COPY_FAILED` を記録して、その ZIP の処理を中断する      |
| ZIP の中の ZIP が、深さ 3 を超える     | 警告として記録する。その ZIP の中身は、取り込まない      |
| Takeout の json に、対応する写真がない | 無視する(件数のみ記録)                                   |

## 10. 受け入れ条件

- ZIP の中の写真・動画が、通常のファイルと同じ規則でコピーされること。
- 元の ZIP が、変更されないこと。
- 取り出した一時ファイルが、処理のあと、すぐ削除されること。
- 深さ 4 以上の入れ子が、開かれず、警告として記録されること。
- パスが危険なエントリが、展開されず、エラーとして記録されること。
- cp932 のファイル名が、文字化けせずに、記録されること。
- Takeout の json から、日付が取れ、「フォールバック(json)」として記録されること。
