# 機能: 日付の決定とフォールバック(date-resolution)

## 1. 目的

ファイルの撮影日時を決め、保存先の置き場所と名前に反映する。ファイル本体から日付が取れなかったものは「日付フォールバック」として記録し、一覧で確認できるようにする。

## 3. 日付の取得元と優先順位

| 優先 | 取得元                                                                      | 区分                                         |
| :--- | :-------------------------------------------------------------------------- | :------------------------------------------- |
| 1    | EXIF の DateTimeOriginal(写真・RAW)。なければ DateTimeDigitized、CreateDate | 通常                                         |
| 2    | 動画の CreateDate(UTC をローカル時刻へ変換)                                 | 通常                                         |
| 3    | Takeout の `.json` の撮影日時                                               | フォールバック(`json`)                       |
| 4    | ファイル名に含まれる日付                                                    | フォールバック(`filename`)                   |
| —    | ファイルの更新日(mtime)                                                     | 日付として**採用しない**。参考情報として記録 |

- 更新日(mtime)は、書き換わっていて信頼できないため、採用しない ([日付の代替の取得元](../requirements.md#d-02))。実データでは、本体のメタデータの年と、更新日の年が違うものが、写真で約 3%(297 / 9,608)あった。ZIP の中のファイルの更新日は、ZIP に詰めた日時になるため、485 / 485 件がすべて違った(PoC)。
- 優先順位1・2で取れなかった時点で「フォールバック」とする ([日付フォールバックの記録](../requirements.md#d-03))。

## 4. ファイル名からの日付の読み取り(仮)

次のようなパターンから、日付を取り出す。取れる精度に応じて、`full` / `date` / `month` / `year` と判定する。

| 例                                   | 読み取り結果                                                       |
| :----------------------------------- | :----------------------------------------------------------------- |
| `IMG_20240501_123456.jpg`            | 2024-05-01 12:34:56(`full`)                                        |
| `PXL_20240501_123456789.jpg`         | 2024-05-01 12:34:56(`full`。ミリ秒は無視)                          |
| `2024-05-01 12.34.56.jpg`            | 2024-05-01 12:34:56(`full`)                                        |
| `20240501.jpg`                       | 2024-05-01(`date`)                                                 |
| `2024-05.jpg`                        | 2024-05(`month`)                                                   |
| `1400000000000.jpg`                  | 13 桁のエポックミリ秒(UTC)→ 本機のタイムゾーンへ変換(`full`)       |
| `line_1400000000000.jpg`             | 同上(接頭辞の `line_` は無視)                                      |
| `2014-04-01-12-30-45_photo.jpg`      | 2014-04-01 12:30:45(`full`。`-123` のようなミリ秒が続く場合は無視) |
| `20140401_123456_r.jpg`              | 2014-04-01 12:34:56(`full`。末尾の `_r` などは無視)                |
| `Screenshot_2024-05-01-12-34-56.png` | 2024-05-01 12:34:56(`full`)                                        |
| `zb2014-04-01_12-34-56.jpg`          | 2014-04-01 12:34:56(`full`)                                        |
| `15-09-06-15-48-35-995_photo.jpg`    | 2015-09-06 15:48:35(`full`。年が 2 桁。2000 年代として読む。ミリ秒まで揃った形だけ) |
| `IMG_0001.jpg`                       | 取れない                                                           |

- **13 桁のエポックミリ秒**は、2000-01-01 から実行時点までの範囲に収まる場合だけ、日付として採用する。範囲外は、無効(ただの番号)として扱う。
- 実データ(約 1.5 万ファイル)で多かった形を、優先して対応する: `IMG_####.JPG`・`DSC_####.JPG` のような連番だけの名前は、日付を含まないので、本体のメタデータに頼る。`CM######-#########` のように意味が確定できない形は、読み取らない。
- 数字の並びが偶然、日付に見える場合(`IMG_20240230.jpg` のように存在しない日、`IMG_1234.jpg` のような連番)は、**無効**として、取れなかったものにする。
- **年が 2 桁の形**(`yy-mm-dd-hh-mm-ss-mmm`)は、連番との誤認を避けるため、区切りが `-` で、時分秒とミリ秒(3 桁)まで揃っている場合だけ、読む。実データ(約 1.3 万枚の写真)で、ファイル名から日付を読んだ約 2,300 枚のうち、264 枚を占めた(PoC)。
- パターンの一覧は設定で追加できるようにする。(仮)

## 5. 日付の精度と置き場所

| 精度             | 置き場所                     | ファイル名                     |
| :--------------- | :--------------------------- | :----------------------------- |
| `full`           | `YYYY/MM/`                   | `YYYY.MM.DD_HH-MM-SS_<元の名前>.<拡張子>` |
| `date`           | `YYYY/MM/_時刻不明/`         | `YYYY.MM.DD_<元の名前>.<拡張子>` |
| `month`          | `YYYY/MM/_日付不明/`         | `YYYY.MM_<元の名前>.<拡張子>`  |
| `year`           | `YYYY/_月日不明/`            | `YYYY_<元の名前>.<拡張子>`     |
| `none`           | `_unknown/日付なし/`         | `<元の名前>.<拡張子>`          |
| `invalid`        | `_unknown/日付が不正/`       | `<元の名前>.<拡張子>`          |
| 修復後も日付なし | `_unknown/修復後も日付なし/` | `<元の名前>.<拡張子>`          |

- 名前が衝突したら、名前の最後(拡張子の前)に連番(`_01`、`_02` …)を付ける。元の名前の整え方(使えない文字、長さの上限)は、仕様書 §2-2。
- フォルダ名の先頭の `_` は、並び順で先頭に来るようにするため。

## 6. タイムゾーン(仮)

- 写真: EXIF にオフセットがあれば、その時刻をそのまま使う。なければ、書かれている値を、そのままローカル時刻として扱う。
- 動画: UTC で記録されていることが多いので、本機のタイムゾーンへ変換する。
- 日付をまたぐ近くの時刻(23:59 と 0:01 など)は、変換後のローカル時刻で日付を決める。

## 7. 無効な日付

次の値は「取れなかった」として、次の優先順位の取得元に進む。

- `0000:00:00 00:00:00` などの空の日付
- 1970 年より前、または実行時点より未来
- 存在しない日付(13月、2月30日など)

すべての取得元で無効だった場合は `invalid`、何もなければ `none` とする。

## 8. 同名グループでの日付

RAW+JPEG やライブフォトなどの同名グループは、**グループ内で最も精度の高い取得元**で、1回だけ日付を決める。全員が、同じ置き場所と名前の語幹を共有する ([RAW と JPEG のペア](../requirements.md#i-05))。

- 例: JPEG に日付がなく、RAW の EXIF に日付がある場合は、RAW の日付を JPEG にも使う。
- 「最も精度の高い取得元」は、次の順で決める。
  1. 取得元の確かさ: EXIF・動画 > Takeout の json > ファイル名(日付が有効なものが、有効でないものより優先)
  2. 同じなら、日付の精度: `full` > `date` > `month` > `year`
  3. それでも同じなら、名前順で先頭のファイル(入力の順番に、結果が左右されないようにするため)
- 日付を決めたファイルが、グループの代表。その元の語幹(`-video-paired` などの接尾辞を除いたもの)を、全員の出力名に使う。
- どのファイルも有効な日付を持たないとき、無効な値が 1 つでもあれば `invalid`、なければ `none`。

## 9. 日付フォールバック一覧(Web)

| 列           | 内容                             |
| :----------- | :------------------------------- |
| ファイル     | 元の場所、保存した場所           |
| 決定した日付 | 日付と、その精度                 |
| 取得元       | `json` / `filename` / `none`     |
| 理由         | 本体のメタデータになかった、など |
| 参考の更新日 | mtime                            |

- 取得元の種別(`json` / `filename` / `none`)で、絞り込める ([フォールバック一覧の絞り込み](../requirements.md#d-05))。
- 日付の精度でも、絞り込める。
- 取得元の種別が `none` のものは、`_unknown/` に入っているファイル。Web で場所を確認できる。

## 10. 受け入れ条件

- 優先順位のとおりに日付が採用され、取得元の種別が記録されること。
- 更新日(mtime)が、日付として採用されないこと。
- 精度ごとに、仕様書 §2-2 の置き場所と名前になること。
- 無効な日付(0000・未来・存在しない日)が、採用されないこと。
- 本体のメタデータから取れなかったものが、すべて日付フォールバック一覧に載ること。
- 動画の UTC が、本機のタイムゾーンへ変換されること。
- 同名グループが、同じ置き場所と名前の語幹になること。
