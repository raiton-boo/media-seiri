# 機能: dry-run(dry-run)

## 1. 目的

ファイルを一切コピーせず、「実行したら、何が起こるか」の結果だけを見る。本実行の前に、件数・容量・問題点を確認するために使う。

## 2. 関連する要件

X-01〜X-03, V-04
仕様書: §11 / フロー: `flows.md` 1章

## 3. 何をするか・しないか

| する                                                             | しない                                           |
| :--------------------------------------------------------------- | :----------------------------------------------- |
| ソースのスキャン                                                 | 保存先へのコピー                                 |
| メタデータの取得                                                 | サムネイルの作成                                 |
| ハッシュの計算(キャッシュを使う。新規の結果は、キャッシュに保存) | ソースへの書き込み(これは、通常の実行でもしない) |
| 重複の判定                                                       | 保存先のフォルダの作成                           |
| 置き場所と名前の決定                                             | 保存先のロックの取得(読み取りだけなので、不要)   |
| 修復の**検出**(破損の検出まで)                                   | 修復の実行(`repaired/` への書き込み)             |
| 容量の見積り                                                     |                                                  |
| ZIP の中身の一覧と読み取り(一時領域に取り出して、すぐ削除)       |                                                  |

- 書き込むのは、作業用の台帳(`data/`)と、一時領域だけ。保存先には、書き込まない。
- 修復は、実行しない。破損として検出し、「修復の対象」として件数を報告する。(仮)

## 4. 結果の出力

### 4-1. CLI(サマリー)

```text
  ソース        : Backup-HDD (USB / HDD / 1.8 TB)
  保存先        : Library-2024 (exFAT / 空き 1.2 TB)

  検出          : 15,610 ファイル  (写真 11,200 / 動画 3,100 / RAW 1,310)
  コピー予定    : 14,820 ファイル   124.3 GB
  重複スキップ  :    650 ファイル
  日付フォールバック :  95 ファイル  (json 20 / filename 75)
  日付なし(_unknown) :  30 ファイル
  破損(修復の対象)  :   10 ファイル
  対象外        :     5 ファイル(.aae など)
  エラー        :      3 ファイル

  必要な容量    : 130.5 GB(余裕分 6.2 GB を含む)
  保存先の空き  : 1.2 TB         →  足りています
```

(数値は例)

### 4-2. レポートの出力(仮)

```text
file-seiri ingest ... --dry-run --report <ファイル>
```

- 結果を、ファイル(CSV または JSON)に書き出せる。ファイルごとに、コピー予定の場所と名前、判定の理由を含む。
- 書き出し先は、保存先ではなく、指定の場所(または `data/`)。

## 5. Web での確認 [X-03]

- dry-run の結果も、Web で見られる(実行の履歴に、「dry-run」の印つきで表示)。
- 「コピー予定の一覧」「重複スキップの一覧」「日付フォールバック一覧」「エラー一覧」を、通常の実行と同じ画面で見られる。
- 通常の集計(アルバム・地図・統計・重複比較)には、**含めない**(台帳に、`is_dry_run = 1` として記録する)。
- 画面で、dry-run の結果であることを、明示する。

## 6. 本実行との関係

- dry-run の結果は、本実行のコピー結果と一致することを目指す。ただし、実行までの間に、ソースや保存先が変わっていれば、変わりうる。
- dry-run のあとの本実行は、同じコマンドから `--dry-run` を外して実行する。dry-run で計算したハッシュは、キャッシュされているので、本実行は速くなる。
- dry-run の結果を、本実行にそのまま「適用」する機能は、作らない(状況が変わっている可能性があるため)。

## 7. エッジケース

| 状況                                     | 振る舞い                                                       |
| :--------------------------------------- | :------------------------------------------------------------- |
| 保存先のドライブが、接続されていない     | 容量の見積りができない旨を表示し、そのほかの結果は出す。(仮)   |
| 保存先がまだ、ライブラリになっていない   | 空のライブラリとして、見積りをする。ライブラリは、作らない     |
| 保存先が、NTFS などで書き込めない        | 検査の結果を、警告として表示する(dry-run では、止めない)。(仮) |
| 同じ内容の複数のファイルが、ソースにある | 先に確定した1件を採用、残りをスキップとして報告する            |
| dry-run を、何度も実行                   | 実行のたびに、`runs` に記録する                                |

## 8. 受け入れ条件

- 保存先に、何も作られず、何も書き込まれないこと。
- コピー予定・重複・フォールバック・エラー・容量の見積りが、報告されること。
- 結果が、Web で、dry-run の印つきで見られること。
- アルバム・地図・統計・重複比較の集計に、含まれないこと。
- ハッシュキャッシュが、本実行で使われること。
- 保存先の容量が足りない場合に、警告されること。
