# 機能: 複数ソースとライブラリ(multi-source)

## 1. 目的

- 外付け HDD・USB メモリなどを、1つずつ別々に取り込んでも、それまでの結果が失われたり、上書きされたりしないようにする。
- 保存先を「ライブラリ」として扱い、別の HDD への移行や、他の PC での閲覧ができるようにする。
- ドライブの取り違えを防ぐ。

## 3. ライブラリとは

整理済みの写真が入った1つのフォルダ(ライブラリの根)と、それを説明する台帳・サムネイルのひとまとまり。

```text
<保存先ドライブ>/
├── Pictures/                          ← ライブラリの根
│   ├── .file-seiri-library.json       ← 目印(ライブラリ ID)
│   ├── 2024/05/ ...
│   ├── _unknown/ ...
│   └── .file-seiri/
│       ├── catalog.snapshot.sqlite    ← 台帳のコピー
│       └── thumbs/                    ← サムネイル
└── viewer/                            ← 閲覧用プログラム
```

- 目印ファイルの**ライブラリ ID** で、どのライブラリかを識別する(ドライブの名前では識別しない) ([ライブラリの目印ファイル](../requirements.md#m-05))。
- 台帳のパスは、ライブラリの根からの**相対パス**([相対パスで記録](../requirements.md#m-06))。

## 4. 複数ソースの取り込み

### 4-1. 基本

- 外付けごとに、別々に実行できる ([ソースごとの実行](../requirements.md#m-01))。
- 実行(run)ごとに ID を付け、ソース、開始・終了時刻、件数を記録する ([実行 ID](../requirements.md#m-03))。
- 台帳は、ライブラリごとに1つで、実行を重ねるごとに累積する。過去の実行の記録は、消えない・上書きされない ([過去の結果を失わない](../requirements.md#m-02))。
- ソースが複数の場合は、1つずつ順番に処理する(同じハブの USB の帯域を奪い合わないため) ([ソースは 1 つずつ処理](../requirements.md#v-06))。

### 4-2. 同じソースの再実行 (要件: [再実行で二重コピーしない](../requirements.md#m-04))

- 処理済みのファイル(同じボリューム・相対パス・サイズ・mtime)は、スキップする。(仮)
- 処理済みかどうかの判定は、`source_files` の記録と、ハッシュキャッシュによる。
- ソースにあとから、ファイルが追加されていれば、追加分だけが取り込まれる。

### 4-3. 中断と再開

- 実行の状態は、ファイルごとに保存される。中断(Ctrl-C、ドライブが抜けた、強制終了など)しても、`ingest --resume` で、同じ実行 ID のまま、終わっていないファイルだけを続けられる。
- 中断された実行は、`runs.status = interrupted` として残る。強制終了などで `running` のまま残ったものは、次の本実行が、ロックを引き継ぐときに、`interrupted` にする(仕様書 §12)。
- 記録する前に止まったコピーは、次の本実行の起動時に、保存先のファイルを採用する(仕様書 §8-3)。

## 5. ドライブの選択 (要件: [ドライブの一覧](../requirements.md#v-01)〜[保存先とソースが同じなら停止](../requirements.md#v-03))

### 5-1. 一覧

```text
file-seiri drives
```

| 列         | 内容                                         |
| :--------- | :------------------------------------------- |
| 名前       | ボリューム名                                 |
| 容量・空き |                                              |
| 形式       | exFAT / APFS / NTFS / FAT32 など             |
| 種類       | USB / 内蔵、HDD / SSD                        |
| 状態       | 書き込み可 / 読み取り専用                    |
| ライブラリ | ライブラリの目印があれば、その ID と最終更新 |

### 5-2. 取り違えの防止

- ドライブは、名前ではなく、**ボリュームの固有 ID** で識別する。同じ名前の USB メモリが複数あっても、取り違えない ([ボリューム ID で識別](../requirements.md#v-02))。
- 保存先とソースが同じドライブなら、実行を止める ([保存先とソースが同じなら停止](../requirements.md#v-03))。
- 実行前に、「ソース → 保存先」と、容量チェックの結果を表示して、利用者の確認を取る。

### 5-3. 保存先の検査 (要件: [出力先のドライブの形式](../requirements.md#c-09)、[保存先の書き込み・形式チェック](../requirements.md#v-05))

| 状態                                           | 振る舞い                         |
| :--------------------------------------------- | :------------------------------- |
| 読み取り専用(NTFS を Mac で開いている場合など) | 理由を表示して止める             |
| NTFS                                           | Mac から書き込めないため、止める |
| FAT32 で、4GB 以上のファイルがコピー予定にある | 止める                           |
| exFAT / APFS など、書き込み可                  | 続行                             |
| ライブラリの目印がない                         | `library init` で作るか確認する  |

## 6. 容量チェック (要件: [容量チェック](../requirements.md#v-04))

- 必要量 = コピー予定のファイルの合計サイズ(重複スキップ分は除く) + 余裕分(`max(5%, 10GB)`。仮)。
- 保存先の空きが足りなければ、不足分を表示して、実行を止める。
- 作業用の領域(`data/`)の空きも確認する(ZIP 内の最大の1ファイル分 + 修復用の領域)。
- dry-run でも、同じ見積りを表示する(`dry-run.md`)。

## 7. ライブラリの作成と移行

### 7-1. 作成

```text
file-seiri library init <保存先のパス>
```

- ライブラリの根に、目印ファイルを作り、台帳の初期化をする。空のドライブから始める ([既存の写真の登録(index)はスコープ外](../requirements.md#m-10))。

### 7-2. 別の HDD への移行

1. 新しい HDD(exFAT など)をつなぐ。
2. ライブラリの根のフォルダを、**フォルダごと**新しい HDD にコピーする(`viewer/` も一緒に)。
3. `file-seiri verify --library <新しい場所>` で、全ファイルを、台帳のハッシュと照合する(`hash-verify.md`)。
4. 一致を確認したら、この Mac が、ライブラリ ID で同じライブラリだと認識し、新しい場所を、設定に記録する。
5. 古い HDD のデータの削除は、利用者が手動で行う。

- 台帳は、相対パスなので、書き換えは不要 ([相対パスで記録](../requirements.md#m-06))。
- 移行の途中で、一部のファイルだけが壊れた場合は、`verify` が不一致として報告する。

## 8. 台帳の置き場所とスナップショット

- 作業用の台帳は、この Mac の `data/libraries/<ライブラリID>/` に置く ([作業用の台帳の置き場所](../requirements.md#m-07))。
- 実行の最後に、台帳のコピー(スナップショット)を、ライブラリの `.file-seiri/` に保存する ([スナップショットの保存](../requirements.md#m-08))。
- 台帳のリビジョン番号を比べて、ライブラリのスナップショットが新しい場合は、自動で上書きせず、利用者に確認する(この Mac の `data/` を失った場合の、復元に使う)。

## 9. 閲覧専用ビューア(他の PC)

- 家の PC では、ドライブをつなぎ、`viewer/` のプログラムを開くだけで、ブラウザにアルバムが出る ([家の PC で閲覧](../requirements.md#w-01)、[単体の実行ファイル](../requirements.md#w-02))。
- スナップショットとサムネイルを、読み取り専用で開く。書き込みは行わない(Web は、すべてのモードで閲覧専用) ([Web は閲覧専用](../requirements.md#w-03))。
- 台帳が相対パスのため、ドライブ文字・マウント先が変わっても動く ([ドライブ文字が変わっても動く](../requirements.md#w-04))。
- 詳細は、`web-viewer.md`(予定)で定める。

## 10. エッジケース

| 状況                                       | 振る舞い                                               |
| :----------------------------------------- | :----------------------------------------------------- |
| 同じ名前のドライブが複数ある               | 固有 ID で識別し、一覧に容量などを併せて表示する       |
| 保存先のドライブが、実行中に抜けた         | 実行を中断する。再接続後に、再開できる                 |
| スナップショットが、作業用の台帳より新しい | 利用者に確認する。自動で上書きしない                   |
| 別のライブラリのドライブを指定した         | ライブラリ ID が違うことを表示し、続行するかを確認する |
| 2つのライブラリを作った                    | 互いに独立。ライブラリ間の重複は検出しない ([ライブラリごとに台帳が独立](../requirements.md#m-09))      |

## 11. 受け入れ条件

- 別々の外付けを、順番に取り込んでも、前の実行の記録が残ること。
- 同じソースを再実行しても、処理済みのファイルが、二重にコピーされないこと。
- 保存先とソースが同じドライブの場合に、実行が止まること。
- 同名のドライブが複数あっても、取り違えずに選べること。
- 読み取り専用・NTFS・容量不足の保存先に、書き込もうとしないこと。
- ライブラリのフォルダを、別のドライブへ丸ごとコピーしても、`verify` で一致が確認でき、そのまま使えること。
- ドライブ文字が変わっても、閲覧専用ビューアが動くこと。
