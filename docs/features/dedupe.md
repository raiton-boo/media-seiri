# 機能: 重複検出(dedupe)

## 1. 目的

内容が完全に同じファイルを、自動でスキップして記録する。スキップしたものと、採用したものを、Web の比較画面で確認できるようにする。

「別物」判定(重複を別のファイルとして追加コピーする操作)は、今回は作らない(スコープ外)。

## 2. 関連する要件

P-01〜P-03, I-04, I-05, M-09, L-04
仕様書: §5 / ER: `duplicate_links`

## 3. 重複の判定

- **ハッシュが完全に一致する**ものだけを、重複とする [P-01]。
- 名前・日時・サイズが同じだけでは、重複にしない。
- 見た目が似ている写真(リサイズや再圧縮したもの)は、対象外(スコープ外)。
- 比較の対象は、**同じライブラリの台帳全体**(過去の実行も含む)。ライブラリが別なら、互いの重複は検出しない [M-09]。
- RAW+JPEG の同名ペアは、拡張子が違い、内容も別なので、重複にならない [I-05]。

## 4. 自動スキップ [P-02]

1. ハッシュがカタログの内容と一致したら、コピーしない。
2. 「採用側」(すでにライブラリにあるファイル)と「スキップ側」(今回のソースのファイル)の対応を、`duplicate_links` に記録する。
3. 同一の実行の中で、同じ内容が複数ある場合は、先に処理が確定した1件を採用し、残りをスキップする。(仮)
4. スキップしたファイルは、ソース側に、そのまま残る(ソースは変更しない)。

## 5. 重複比較の画面(Web) [P-03]

Web は、閲覧専用。ファイルの変更・コピー・削除の操作は、持たない。

### 5-1. 一覧

| 列                   | 内容                                                                 |
| :------------------- | :------------------------------------------------------------------- |
| スキップしたファイル | 元の場所(ソースのボリューム、パス。ZIP 内なら、ZIP のパスと中のパス) |
| 採用したファイル     | ライブラリの中の場所                                                 |
| 実行                 | どの実行でスキップしたか                                             |

- ソースのボリューム、実行で、絞り込める。
- 件数が多いため、一覧は、重複のグループごとにまとめる(同じ内容のスキップ側を、1つの採用側の下に並べる)。

### 5-2. 比較

- 採用側とスキップ側を、**並べて表示**する(サムネイル、サイズ、更新日、メタデータ、ハッシュ)。
- ハッシュが一致していることを、画面に明示する。
- ドライブが接続されていない場合は、サムネイルだけを表示する。

## 6. 重複をなくしたあとの扱い(スコープ外)

- 重複のスキップ側を、別のファイルとして残す操作は、作らない。
- 将来、必要になった場合は、次の方針で追加する。
  - 追加コピーの元は、ソースではなく、**ライブラリにある採用側のファイル**にする(内容が完全に同じため、ソースのドライブの接続が不要で、速く、安全)。
  - そのために、ER に状態の列と、ジョブのテーブルを追加する(`er.md` 3-5)。
  - Web が、ファイルを書き込むことになるため、書き込みの排他制御と、動作モードを見直す(`specification.md` §12)。

## 7. エッジケース

| 状況                                                             | 振る舞い                                                                                                                  |
| :--------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------ |
| 採用側のファイルが、ライブラリから消えている(手動で削除した場合) | `verify` で欠落として検出する。次の取り込みでは、ソース側のファイルが、再度コピーされる(台帳の採用側が、無効のため)。(仮) |
| 同じ内容のファイルが、ZIP の中と外にある                         | どちらも、同じ内容として扱う。先に確定した1件を採用する                                                                   |
| 採用側が、修復済みのファイル                                     | 重複判定は、修復後のハッシュで行う(`repair.md`)                                                                           |

## 8. 受け入れ条件

- ハッシュが同じファイルが、コピーされずにスキップされ、採用側との対応が記録されること。
- ハッシュが違うファイルは、名前や日時が同じでも、重複にならないこと。
- 比較画面で、採用側とスキップ側が並べて表示されること。
- Web から、ファイルを変更する操作が、できないこと。
- ライブラリが違うと、互いの重複が検出されないこと。
