# 機能: 取り込み(ingest)

## 1. 目的

ソース(外付け・内蔵ストレージ)の写真・動画・RAW を、撮影日時をもとに、保存先のライブラリへコピーして整理する。本ツールの中核となる機能。

## 2. 関連する要件

C-02, C-03, C-04, C-05, I-01〜I-09, T-01〜T-06, U-01〜U-08, V-01〜V-06, X-01〜X-03

## 3. 利用者から見た振る舞い

### 3-1. 実行の流れ

1. ソースと保存先のドライブを選ぶ(一覧から、または引数で指定)。
2. 保存先を検査し、容量チェックの結果を確認する。
3. 取り込みを実行する。CLI に、処理中のファイルと進捗がライブ表示される。
4. 終了すると、サマリー(採用 / 重複スキップ / 日付フォールバック / エラー)が表示される。
5. 結果は、Web で閲覧できる。

### 3-2. 何をするか

- ソース配下を再帰的にスキャンし、対象の拡張子のファイルを検出する(§1-1)。
- メタデータから日付を決め、置き場所と名前を決める(`date-resolution.md`)。
- 内容が同じものは重複としてスキップする(`dedupe.md`)。
- 新しいものだけを、一時ファイルに書き、ハッシュで照合してから正式名にする(`hash-verify.md`)。
- ソースのファイルは、変更も削除もしない [C-03]。コピーしたファイルの更新日は、引き継がない [I-08]。

### 3-3. 対象外・除外

- 対象外のサイドカー(`.aae` / `.thm` / `.lrv` など)は、コピーせず、件数だけ記録する。
- 管理用のファイル(`._*`、`.DS_Store` など)、空ファイルは、取り込まない(空ファイルはエラー一覧に記録する)。
- 保存先のライブラリの根と、作業用の `data/` は、スキャンしない。

## 4. 操作(CLI。コマンド名は仮)

| コマンド                                     | 内容                                          |
| :------------------------------------------- | :-------------------------------------------- |
| `file-seiri drives`                          | 接続中のドライブの一覧を表示する [V-01]       |
| `file-seiri ingest`                          | ソースと保存先を対話で選んで実行する          |
| `file-seiri ingest <ソース> --dest <保存先>` | 引数で指定して実行する                        |
| `file-seiri ingest ... --dry-run`            | コピーせず、結果だけを出す(`dry-run.md`)      |
| `file-seiri ingest ... --resume`             | 中断した実行を再開する(§8-3)                  |
| `file-seiri ingest ... --rehash`             | ハッシュキャッシュを使わず、計算し直す [H-03] |

- 複数のソースを指定した場合は、1つずつ順番に処理する [V-06]。
- Web には、取り込みを開始する操作はない。初回の取り込みは CLI で行う [C-04]。

## 5. 画面表示

### CLI(ライブ表示)

- 処理中のファイル、スループット(MB/s)、残り時間の目安
- 件数のカウンター: 採用 / 重複スキップ / 日付フォールバック / エラー
- 色・進捗バー・バナーなどの見た目にもこだわる [L-01]
- 詳細な表示は、`cli-logging.md`(予定)で定める

### Web

- 実行状況を、リアルタイムで見られる [L-03]。

## 6. エッジケース

| 状況                                                   | 振る舞い                                                                                              |
| :----------------------------------------------------- | :---------------------------------------------------------------------------------------------------- |
| 保存先が読み取り専用(NTFS を Mac で開いている場合など) | 理由を表示して実行を止める(`DEST_NOT_WRITABLE`)                                                       |
| 保存先が FAT32 で 4GB 超のファイルがある               | 実行を止める(`DEST_FORMAT_UNSUPPORTED`)                                                               |
| 容量が足りない                                         | 不足分を表示して実行を止める(`CAPACITY_SHORTAGE`)                                                     |
| 実行中にドライブが抜けた                               | 該当のファイルをエラーとして記録し、実行を中断する。再開できる状態で残す                              |
| 同じソースを再実行                                     | 処理済みのファイル(同じボリューム・相対パス・サイズ・mtime)はスキップする(仮)                         |
| 一時ファイルが残っている(前回の中断)                   | 次回起動時に削除する                                                                                  |
| ファイル名が長すぎる・使えない文字を含む               | 出力名は日付などから作るので問題にならない。元の名前を使う場合は、使えない文字を `_` に置き換える(仮) |
| Windows 由来の NFD / NFC 違いの日本語名                | 出力名は NFC に統一する(仮)                                                                           |

## 7. 受け入れ条件

- ソースのファイルが、変更も削除もされないこと。
- 出力先の既存ファイルが、上書きされないこと [I-06]。
- 日付の精度ごとに、仕様書 §2-2 の置き場所と名前でコピーされること。
- コピーしたファイルのハッシュが、ソースと一致すること(不一致は、成功にしない)。
- RAW+JPEG のペアが、同じ名前の語幹で並ぶこと [I-05]。
- 同名で内容が違うファイルが、連番で追加コピーされること [I-04]。
- 実行中でも、Web から進捗が見えること。
- 中断後、同じコマンドで再開でき、処理済みを二重にコピーしないこと。
