# 機能: ハッシュ・検証・キャッシュ(hash-verify)

## 1. 目的

- コピー中の破損(転送中の化け、書き込みの失敗)を、確実に検出する。
- 同じファイルのハッシュを何度も計算しないよう、結果をキャッシュして、速度を確保する。
- ライブラリ全体を、あとから検査できるようにする(`verify`)。

## 3. ハッシュの用途

| 用途             | 内容                                                       |
| :--------------- | :--------------------------------------------------------- |
| 重複判定         | 同じハッシュ = 同じ内容 ([完全一致だけを重複とする](../requirements.md#p-01))                             |
| コピーの検証     | ソースのハッシュと、コピー後のハッシュを比較 ([コピー後のハッシュ照合](../requirements.md#h-01))        |
| ライブラリの検査 | `verify` で、台帳のハッシュと、現在のファイルを比較 ([ライブラリ全体の再照合(verify)](../requirements.md#h-06)) |

- アルゴリズムは、**SHA-256** ([SHA-256](../requirements.md#h-05))。標準のコマンド(`shasum -a 256`、Windows の `Get-FileHash`)で、ツールなしに、独立して検証できる。

## 4. コピー時の検証の流れ

1. **1回の読み出し**で、ソースを読みながら、ハッシュ計算と、一時ファイルへの書き込みを同時に行う。
2. 書き終えたあと、**OS のキャッシュを経由せずに**、出力先を読み直して、ハッシュを計算する。
3. ソースのハッシュと比較する。
4. 一致したら、上書きしない方法で、正式名にする。
5. 不一致なら、一時ファイルを削除し、`HASH_MISMATCH` をエラーとして記録する。ソースには触らない ([照合失敗の記録](../requirements.md#h-04))。

- 2 を、OS のキャッシュを避けて行うのは、書き込み直後の読み出しが、ディスクではなくメモリから返り、本当の破損を見逃すのを避けるため。
- 検証に失敗したファイルは、成功扱いにしない。エラー一覧に載せ、再実行で、再度コピーされる。

## 5. ハッシュキャッシュ

### 5-1. キー

(ボリューム識別子, ボリューム内の相対パス, サイズ, mtime[ミリ秒の整数])

- 外付けは、接続するたびにマウント先が変わるため、パスだけをキーにしない。
- サイズか mtime が変わったら、キャッシュは無効として、再計算する。

### 5-2. 使い方

| 操作       | 内容                                                |
| :--------- | :-------------------------------------------------- |
| 通常       | キャッシュがあれば、ハッシュの計算を省略する ([ハッシュのキャッシュ](../requirements.md#h-02)) |
| `--rehash` | キャッシュを無視して、全て計算し直す ([キャッシュを使わない再計算](../requirements.md#h-03))         |

- dry-run でも、キャッシュを使い、新しく計算したものはキャッシュに保存する(重複判定に必要)。
- キャッシュは、台帳(`hash_cache`)に持つ。

## 6. verify(ライブラリの検査)

```text
file-seiri verify [--library <パス>] [--sample <割合>]
```

- ライブラリの全ファイルのハッシュを、キャッシュを使わず計算し直して、台帳と照合する ([ライブラリ全体の再照合(verify)](../requirements.md#h-06))。
- 結果: 一致 / 不一致 / 欠落(台帳にあるがファイルがない) / 未登録(ファイルはあるが台帳にない)。
- 不一致・欠落は、`VERIFY_MISMATCH` としてエラー一覧に記録する。未登録は、報告のみ。
- ファイルの修復や削除は行わない。
- 使う場面: ライブラリを別の HDD にコピーしたあと(`multi-source.md` の移行手順)、または、定期的な点検。
- `--library <パス>`: 対象のライブラリの根。省くと、この Mac に登録されたライブラリが 1 つだけなら、それを使う(複数あれば、案内して止める)。目印がないときは、ライブラリを作る確認はせず、案内して止める。
- `--sample <割合>`: 全件ではなく、一部だけを抜き取って検査する(時間を短縮したい場合)。割合は `0.1` や `10%`(0 より大きく 1 以下)。台帳のファイルの数 × 割合(切り上げ、最低 1 件)を、実行のたびに無作為に選ぶ(繰り返すと、別のファイルが、検査される)。未登録の探索は、抜き取りでも、全体を調べる(軽いため)。
- **照合の手順**: 台帳のファイルを、パスの順に、1 つずつ(SSD は並列)読む。ファイルがなければ「欠落」。サイズが台帳と違えば、読まずに「不一致」。読んだら、OS のキャッシュを避けて(`F_NOCACHE`)ハッシュを計算し、台帳と比べる。読めなければ「読み取り不可」(`READ_FAILED`。一致には数えない)。未登録の探索から除くもの: 目印・`.file-seiri/`・付属ファイル(`._X`)・コピーの一時ファイル・ドライブの管理用ファイル。
- **記録**: 検査も「実行」(`runs.kind = verify`)として記録する。不一致・欠落は `VERIFY_MISMATCH` としてエラー一覧に、未登録は WARN のイベント(`VERIFY_UNREGISTERED`)に残す。終わると、リビジョンを +1 して、スナップショットを保存する。書き込みのロックを取る(取り込みと同時に走らせると、結果が食い違うため。取れなければ、保持者を表示して終了)。
- **終了コード**: 0 すべて一致(未登録だけなら 0)/ 1 不一致・欠落・読み取り不可がある / 2 実行できなかった / 130 中断(Ctrl-C。ここまでの結果を記録する)。

## 7. 性能

- コピー時の「1回の読み出し」は、2TB 規模で、読み出しの時間を半減させる [[性能の工夫](../requirements.md#n-05) の1]。
- HDD では、並列の読み出しを避け、順番に読む [[性能の工夫](../requirements.md#n-05) の3]。
- 検証の読み直しは、キャッシュを避けるため、HDD の速度で読まれる。全体の時間には、この読み直しが含まれる。
- DB への書き込みは、まとめてコミットする [[性能の工夫](../requirements.md#n-05) の6]。

## 8. エッジケース

| 状況                               | 振る舞い                                                                                                     |
| :--------------------------------- | :----------------------------------------------------------------------------------------------------------- |
| 読み取り中にエラー(不良セクタなど) | `READ_FAILED` を記録し、そのファイルは、コピーしない(`_unknown/読み取り不可/` への扱いは `repair.md` を参照) |
| コピー中に保存先がいっぱいになる   | `COPY_FAILED` を記録し、一時ファイルを削除する                                                               |
| コピー中に実行が中断される         | 一時ファイルが残る。次回起動時に削除する                                                                     |
| ソースが、コピー中に変更された     | サイズ・mtime が変わっていることを検出した場合は、エラーとして記録し、再度の取り込みの対象にする(仮)         |

## 9. 受け入れ条件

- コピー後のハッシュが一致しないファイルが、正式名にならないこと。
- 不一致が、エラー一覧に記録されること。
- 検証の読み出しが、OS のキャッシュを経由しないこと。
- 2回目の実行で、同じファイルのハッシュが再計算されないこと(`--rehash` なしの場合)。
- `--rehash` で、全ファイルが計算し直されること。
- `verify` が、欠落・不一致・未登録を、区別して報告すること。
- `verify` が、ファイルを変更・削除しないこと。
