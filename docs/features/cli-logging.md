# 機能: CLI の表示とログ(cli-logging)

## 1. 目的

取り込みの進み具合と、起こっていることを、ターミナルで逐次わかるようにする。見た目にもこだわる。ログは、ファイルにも、台帳にも残す。

## 2. 関連する要件

[ログ・進捗](../requirements.md#l-01)、[性能の工夫](../requirements.md#n-05)
仕様書: §13 / ER: `events`, `errors` / フロー: `flows.md` 6章

## 3. 出力の種類

| 出力           | 内容                                             | 向いている用途                       |
| :------------- | :----------------------------------------------- | :----------------------------------- |
| **ライブ表示** | 画面を書き換えながら、進捗とカウンターを表示する | 対話的に、実行を見ているとき         |
| **ログの行**   | 1イベント1行で、流れるように出力する             | 画面の記録、ファイルへのリダイレクト |
| サマリー       | 実行の最後に、結果をまとめて表示する             | 結果の確認                           |

- 標準出力が端末(TTY)でない場合(リダイレクト、パイプ)は、ライブ表示をやめて、ログの行だけを出す。
- 色は、端末が対応している場合だけ使う。`NO_COLOR` が設定されていれば、使わない。

### 4-1. パネルの構成

| パネル               | 内容                                                                                                           |
| :------------------- | :------------------------------------------------------------------------------------------------------------- |
| run                  | ソース ➜ 保存先、進捗のバー、件数と容量、経過・**完了予定の時刻**、残り(直近 1 分の速さ / 全体の平均)、採用・重複・フォールバック・エラー |
| throughput           | 速度のグラフ(1 本 = 0.5 秒。右端が、いま)。現在・平均・最大・検証の速さ                                        |
| pipeline             | スキャン → ハッシュ → コピー → 検証を、流れる印(◆)でつなぎ、段階ごとの進み・件数・速さを 4 本のバーで表示     |
| in flight            | 段階ごとの、処理中のファイル(進みのバーつき)。展開中の ZIP(エントリ n/N)。保存先の空き、`.part`、`._` の削除数、検証の成功・失敗 |
| breakdown            | 種別(写真・動画・RAW・ZIP)と、日付の取得元(メタデータ・ファイル名・なし)の割合                                 |
| integrity            | ソースと検証の SHA-256 の突き合わせ、スリープの抑止の状態、外部通信(0 B)                                       |
| process              | この CLI の実際の CPU・メモリ、時間の内訳(メタデータ・コピー・`fsync`・検証)                                   |
| recent files・alerts | 最近のログと、WARN・ERROR だけの欄                                                                             |

- 処理中のファイルが、どの段階か(スキャン / ハッシュ / コピー / 検証)を表示する。
- ソースが複数ある場合は、全体の進捗(何個目のソースか)も表示する。(本実装で追加)
- ロゴ・バナーは出さない(パネルに、場所を使うため)。音と通知も、付けない。

### 4-2. 見た目の規則

- 画面は、端末の**幅いっぱい**に広げる。幅が変わっても、追従する。
- パネルの中は、濃い紺色で塗る。背景が透明な端末でも、文字が読めるようにするため(配色は、[design.md §6](../design.md))。
- 端末の行数が足りないときは、優先度の低いパネルから省く。

| 端末の行数 | 表示                                                       |
| :--------- | :--------------------------------------------------------- |
| 48 行以上  | すべて(46 行)                                              |
| 41〜47 行  | integrity と process を省く(39 行)                         |
| 28〜40 行  | in flight・breakdown・alerts も省く(25 行)                 |
| 27 行以下  | run・throughput・pipeline だけ(18 行)                      |

### 4-3. キー操作

| キー              | 動作                                                                       |
| :---------------- | :------------------------------------------------------------------------- |
| `p`               | 一時停止 / 再開(止めている間は、経過時間も進めない)                        |
| `l`               | ログの全画面表示 / 戻る                                                    |
| `w`               | Web の結果の画面を開く(本実装。PoC では、案内の表示だけ)                   |
| `q`、`Ctrl-C`     | 安全に停止する(§8)                                                         |

画面の下に、キーの案内を、いつも出す。

### 4-4. スリープの抑止

取り込み中は、`caffeinate -i` で、Mac のスリープを抑止する(全件で約 55 分かかるため)。取り込みのプロセスが終われば、自動で解除される。状態は、integrity パネルに出す。

## 5. ログのレベルと内容

| レベル | 内容の例                                               |
| :----- | :----------------------------------------------------- |
| DEBUG  | 処理の細部(ハッシュ値、キャッシュのヒット)             |
| INFO   | 取り込み・重複スキップ・サムネイル作成などの通常の記録 |
| WARN   | 日付フォールバック、ZIP の深さ超過、修復の試行など     |
| ERROR  | ハッシュ不一致、読み取り失敗、コピー失敗など           |

- 既定は INFO。`--verbose` で DEBUG、`--quiet` で WARN 以上だけを表示する。
- ライブ表示の下部には、WARN 以上を、優先して表示する。

## 6. ログの保存

- 各処理を**イベント**として、台帳(`events`)に記録する。CLI の表示も、Web の実行状況も、ここから作る ([実行状況の Web 表示](../requirements.md#l-03))。
- 同じ内容を、ログファイルにも書き出す(`data/libraries/<ID>/logs/run-<実行 ID>.log`)。実行ごとに、1 ファイル([ログのファイル保存](../requirements.md#l-02))。**実行を終えるとき**(完了・中断・失敗)に、その実行のイベントを、すべて(DEBUG を含む)書き出す(一時ファイルに書いてから、名前を付け替える)。再開した実行は、全体(前の分も含む)を書き直す。書き出せなくても、台帳には残っているため、警告だけ。
- ログファイルの 1 行は、`時刻 レベル #実行 コード メッセージ`(時刻は、本機のタイムゾーン)。画面の制御文字は、含まない。
- 書き込みの先行記録(`COPY_START`)は、利用者には雑音なので、DEBUG にする(通常の表示には、出ない)。
- ログの保存期間・サイズの上限は、設定できる(古いものは、圧縮または削除)。(仮。未実装)

## 7. ログの閲覧 (要件: [ログはターミナルで見る](../requirements.md#l-05))

| 操作                                | 内容                                                                                   |
| :---------------------------------- | :------------------------------------------------------------------------------------- |
| `file-seiri logs`                   | 直近の実行のログを、古い順に表示する(INFO 以上)                                        |
| `file-seiri logs --run <ID>`        | 指定した実行のログを表示する                                                           |
| `file-seiri logs --level WARN`      | 指定したレベル以上を表示する(`--verbose` は DEBUG 以上、`--quiet` は WARN 以上)        |
| `file-seiri logs --tail <N>`        | 最後の N 行だけを表示する                                                              |
| `file-seiri logs --follow`(`-f`)    | 実行中のログを、追いかけて表示する。実行が終わったら終了する(Ctrl-C でも終了する)      |
| `file-seiri status`                 | ロックの保持者(途絶していれば、そう表示)と、直近の実行の状況・最近の実行の一覧を表示する |

- `--library <パス>` で、対象のライブラリの根を指定する(この Mac に登録されたものが 1 つだけなら、省ける)。台帳は、この Mac にあるため、ライブラリのドライブが抜けていても、ログは見られる。
- 台帳は、**読み取り専用**で開く(書き込みのロックは、取らない)。取り込み中でも、見られる。
- 色は、端末のときだけ(`NO_COLOR` が設定されていれば、使わない。仕様書 §13-1)。
- 実行を、種類で見分けられる: 取り込み / 取り込み(dry-run)/ 検査(`runs.kind`)。

- ログの閲覧は、主にターミナルで行う。結果の閲覧は、Web で行う ([ログはターミナルで見る](../requirements.md#l-05))。

## 8. 中断と終了

| 状況                    | 振る舞い                                                                                                                                       |
| :---------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------- |
| Ctrl-C(または q)を、1回押した | 今のファイルの処理を、終えて(または、安全な位置まで進めて)停止する。一時ファイルを削除し、状態を保存して、`interrupted` で終了する。再開できる |
| Ctrl-C を、続けて押した | 強制終了する。次回起動時に、一時ファイルを削除する                                                                                             |
| ドライブが抜けた        | エラーを記録し、中断する                                                                                                                       |

## 9. 終了コード(仮)

| コード | 意味                                         |
| :----- | :------------------------------------------- |
| 0      | 正常終了(エラーなし)                         |
| 1      | 完了したが、エラーのファイルがあった         |
| 2      | 実行できなかった(保存先の検査・容量不足など) |
| 130    | 中断(Ctrl-C)                                 |

## 10. サマリー

実行の最後に、次を表示する。

- 検出・採用(コピー)・重複スキップ・日付フォールバック・エラー・対象外の件数
- コピーしたサイズ、所要時間、平均の速度
- エラーの内訳(コードごと)
- 次にやること(「Web で結果を確認してください」など)
- `dry-run` の場合は、その旨と、容量の見積り(`dry-run.md`)

## 11. 受け入れ条件

- 処理中のファイル・進捗・件数が、逐次表示されること。
- 標準出力が端末でないとき、ライブ表示が出ず、ログの行だけが出ること。
- すべてのログが、台帳とログファイルに記録されること。
- Web で、実行中の状況が、リアルタイムに見られること。
- Ctrl-C で、一時ファイルが削除され、再開できる状態で終了すること。
- 実行の最後に、サマリーが表示されること。
