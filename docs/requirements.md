# 要件定義

状態の凡例: **確定** = ヒアリングで合意済み / **仮** = 暫定案(要確認) / **未決** = 要ヒアリング

## 1. 前提・制約

| 名前 | 内容                                                                                                                                                                                                                                                                               | 状態 |
| :--- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :--- |
| <a id="c-01"></a>外部へ送らない | 写真・動画・台帳のデータは、外部へ送らない。処理はすべてローカルで行う。外部との通信は、背景地図のタイルの取得([オンラインの地図タイル](#c-11))だけに限る                                                                                                                                                     | 確定 |
| <a id="c-02"></a>対象規模 | 対象規模は 2TB 前後、1万枚以上。単発の大掃除が主用途                                                                                                                                                                                                                               | 確定 |
| <a id="c-03"></a>コピー専用 | 整理はコピー専用とする。元のファイルは変更・削除しない(バックアップ目的)。削除は利用者が手動で行う                                                                                                                                                                                     | 確定 |
| <a id="c-04"></a>整理は CLI で行う | 整理(スキャンから取り込みまで)は CLI で行う。Web は、結果の閲覧専用とし、ファイルの書き込み・コピーの操作は持たない                                                                                                                                                                | 確定 |
| <a id="c-05"></a>出力先はライブラリ | 出力先は「ライブラリ」(§8)とし、外付け HDD に置く。ライブラリの中は、年・月のフォルダに分ける(`YYYY/MM/`)                                                                                                                                                                          | 確定 |
| <a id="c-06"></a>開発ルール | 開発ルールは `docs/rules/` に従う                                                                                                                                                                                                                                                  | 確定 |
| <a id="c-07"></a>背景地図つきの地図 | 背景地図つきの地図表示を行う(取得方法は技術選定で決める)                                                                                                                                                                                                                           | 確定 |
| <a id="c-08"></a>整理はこの Mac だけ | 整理(取り込み・修復・コピー)は、開発用のこの Mac だけで行う。家の PC(Windows など)では、保存済みのデータの**閲覧専用**で使う                                                                                                                                                       | 確定 |
| <a id="c-09"></a>出力先のドライブの形式 | 出力先のドライブは、この Mac から読み書きできる形式(exFAT を推奨)でなければならない。NTFS(Mac では読み取り専用)や、4GB 超のファイルを置けない FAT32 には書き込まない                                                                                                               | 確定 |
| <a id="c-10"></a>Docker は使わない | Docker は使わない(取り込みは Mac で直接動かし、ビューアは単体の実行ファイルで配布する)                                                                                                                                                                                             | 確定 |
| <a id="c-11"></a>オンラインの地図タイル | 背景地図は、オンラインの地図タイルを取得して表示する(家の PC もネットワークにつながっている前提)。外部に送られるのは「見ている範囲のタイルの要求」だけで、写真・台帳のデータは送らない。タイルの提供元は、設定で変更できる。ネットにつながらない場合は、ピンと座標の一覧だけ使える | 確定 |

## 2. 対象ファイル

| 名前 | 内容                                                                                                                                                                                                                                                                                  | 状態             |
| :--- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | :--------------- |
| <a id="t-01"></a>対象ファイル | 写真、動画、RAW 系ファイルを対象とする                                                                                                                                                                                                                                                | 確定             |
| <a id="t-02"></a>拡張子の一覧 | 具体的な拡張子の一覧(写真 / 動画 / RAW)                                                                                                                                                                                                                                               | 確定(細部は仕様書) |
| <a id="t-03"></a>ZIP 内のファイル | ZIP 内のファイルも対象とする。ZIP は、ツールが1ファイルずつ一時領域に取り出して処理する(利用者が先に展開する必要はない)                                                                                                                                                               | 確定             |
| <a id="t-04"></a>ZIP の入れ子 | ZIP の入れ子(ZIP の中の ZIP)は深さ3まで開く。それ以上は警告して記録する。ZIP 内のフォルダの階層は、何層でもたどる                                                                                                                                                                     | 確定             |
| <a id="t-05"></a>サイドカー | サイドカーの扱い。Google Takeout の `.json` は日時・GPS の取得元として読む(コピーはしない)。`.xmp` は RAW と同じ日時名で隣にコピーする。`.aae` / `.thm` / `.lrv` などは対象外にして件数だけ記録する。Takeout の json への対応は、実装の優先度が低い(今回の ZIP に Takeout はないため) | 確定             |
| <a id="t-06"></a>年月のフォルダに混在 | 写真・動画・RAW は同じ `YYYY/MM/` 階層に混在させる                                                                                                                                                                                                                                    | 確定             |

## 3. 取り込み(整理)

| 名前 | 内容                                                                                                                        | 状態 |
| :--- | :-------------------------------------------------------------------------------------------------------------------------- | :--- |
| <a id="i-01"></a>再帰スキャン | ソース(外付け・内蔵ストレージ)配下を再帰的にスキャンし、対象ファイルを検出する                                              | 確定 |
| <a id="i-02"></a>メタデータの取得 | 各ファイルから撮影日時・GPS・カメラ情報などのメタデータを取得する                                                           | 確定 |
| <a id="i-03"></a>ファイル名の形式 | 名前は、日付の部分と元の名前をつないだ `<日付の部分>_<元の名前>.<拡張子>` にそろえる。日時がすべて取れたときは `YYYY.MM.DD_HH-MM-SS_<元の名前>.<拡張子>` とする(元の名前の扱いは、仕様書 §2-2)                                                  | 確定 |
| <a id="i-04"></a>同名の連番 | 同じ名前が既にある場合、内容が違えば連番(`_01`、`_02` …)を付けて追加コピーする                                              | 確定 |
| <a id="i-05"></a>RAW と JPEG のペア | RAW と JPEG の同名ペアは、同じ日時名で拡張子違いとして並べて保存し、重複扱いにしない                                        | 確定 |
| <a id="i-06"></a>上書きしない | 出力先の既存ファイルを上書きしない                                                                                          | 確定 |
| <a id="i-07"></a>日付が一部だけのとき | 日付の一部しか取れなかった場合の置き場所と名前は、§4-2 の規則に従う                                                         | 確定 |
| <a id="i-08"></a>更新日を引き継がない | コピーしたファイルの更新日(mtime)は、元のものを引き継がない(コピーした時刻のままにする)                                     | 確定 |
| <a id="i-09"></a>読み取れないファイル | 読み取れない・壊れていて修復もできないファイルは、`_unknown/読み取り不可/` へ、元の名前のままコピーする(バイトが読める限り) | 確定 |

## 4. 日付の決定と置き場所

### 4-1. 日付の決定

| 名前 | 内容                                                                                                                                                                                                         | 状態             |
| :--- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :--------------- |
| <a id="d-01"></a>撮影日時を優先 | ファイル本体のメタデータの撮影日時を優先して使う                                                                                                                                                             | 確定             |
| <a id="d-02"></a>日付の代替の取得元 | 本体のメタデータから取れない場合は、次の順に代替を試す: Takeout の `.json` → ファイル名の日付。**ファイルの更新日(mtime)は、日付として採用しない**(書き換わっていて信頼できないため)。参考情報として記録する | 確定             |
| <a id="d-03"></a>日付フォールバックの記録 | 本体のメタデータから取得できなかった時点で「日付フォールバック」とし、使った取得元の種別(json / ファイル名 / なし)と理由を一覧に記録する                                                                     | 確定             |
| <a id="d-04"></a>日付の優先順位の詳細 | 優先順位の詳細(動画の UTC とローカル時刻、タイムゾーンの扱いを含む)                                                                                                                                          | 確定(細部は仕様書) |
| <a id="d-05"></a>フォールバック一覧の絞り込み | 日付フォールバック一覧は、取得元の種別で絞り込める                                                                                                                                                           | 確定             |

### 4-2. 日付の精度による置き場所と名前

| 名前 | 取れた日付の精度     | 置き場所                     | ファイル名                     | 状態 |
| :--- | :------------------- | :--------------------------- | :----------------------------- | :--- |
| <a id="u-01"></a>日付がすべて取れた | 年月日+時刻(すべて)  | `YYYY/MM/`                   | `YYYY.MM.DD_HH-MM-SS_<元の名前>.<拡張子>` | 確定 |
| <a id="u-02"></a>時刻だけ不明 | 年月日のみ(時刻なし) | `YYYY/MM/_時刻不明/`         | `YYYY.MM.DD_<元の名前>.<拡張子>` | 確定 |
| <a id="u-03"></a>年月だけ | 年月のみ             | `YYYY/MM/_日付不明/`         | `YYYY.MM_<元の名前>.<拡張子>`  | 確定 |
| <a id="u-04"></a>年だけ | 年のみ               | `YYYY/_月日不明/`            | `YYYY_<元の名前>.<拡張子>`     | 確定 |
| <a id="u-05"></a>日付がない | 日付がまったくない   | `_unknown/日付なし/`         | `<元の名前>.<拡張子>`          | 確定 |
| <a id="u-06"></a>日付の値が不正 | 日付の値が不正       | `_unknown/日付が不正/`       | `<元の名前>.<拡張子>`          | 確定 |
| <a id="u-07"></a>修復後も日付がない | 修復後も日付がない   | `_unknown/修復後も日付なし/` | `<元の名前>.<拡張子>`          | 確定 |
| <a id="u-08"></a>読み取り・修復が不可 | 読み取り・修復が不可 | `_unknown/読み取り不可/`     | `<元の名前>.<拡張子>`          | 確定 |

- フォルダ名の先頭の `_` は、フォルダの並びで先頭に来るようにするため。
- 名前が衝突した場合は、いずれも連番(`_01` …)を付ける(元の名前が付くため、衝突は、同じ日時・同じ元の名前の、内容の違うファイルに限られ、ほとんど起きない)。
- 日付がどの精度で取れたかは、DB に記録し、Web の一覧で見られる。

## 8. ライブラリ・複数ソース・再実行

「ライブラリ」とは、整理済みの写真が入った1つのフォルダ(ライブラリの根)と、それを説明する台帳・サムネイルのひとまとまり。

| 名前 | 内容                                                                                                                  | 状態 |
| :--- | :-------------------------------------------------------------------------------------------------------------------- | :--- |
| <a id="m-01"></a>ソースごとの実行 | 外付けごとに別々に実行できる                                                                                          | 確定 |
| <a id="m-02"></a>過去の結果を失わない | 以前の実行結果が、後の実行で失われたり上書きされたりしない                                                            | 確定 |
| <a id="m-03"></a>実行 ID | 実行ごとに ID を付け、どのソースから何をどうしたかを記録する                                                          | 確定 |
| <a id="m-04"></a>再実行で二重コピーしない | 同じソースを再実行しても、処理済みのファイルを二重にコピーしない                                                      | 確定   |
| <a id="m-05"></a>ライブラリの目印ファイル | ライブラリの根に目印ファイルを置き、固有の ID で識別する(ドライブの名前では識別しない)                                | 確定 |
| <a id="m-06"></a>相対パスで記録 | 台帳のパスは、ライブラリの根からの相対パスで記録する。ライブラリのフォルダごと別の HDD にコピーしても、そのまま使える | 確定 |
| <a id="m-07"></a>作業用の台帳の置き場所 | 取り込み中の作業用の台帳は、この Mac のプロジェクト配下(`data/`、git の管理対象外)に置く。保存場所は設定で変更できる  | 確定 |
| <a id="m-08"></a>スナップショットの保存 | 実行の最後に、台帳のコピー(スナップショット)を、ライブラリの中に保存する                                              | 確定 |
| <a id="m-09"></a>ライブラリごとに台帳が独立 | ライブラリが複数ある場合、それぞれの台帳は独立している(ライブラリ間の重複は検出しない)                                | 確定 |
| <a id="m-10"></a>既存の写真の登録(index)はスコープ外 | 保存先のライブラリにすでにある写真の登録(`index`)は、今回は対象外とする(空のドライブから始める)                       | 確定 |

## 13. アルバム(Web)

| 名前 | 内容                                                                                                                                                                | 状態 |
| :--- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------ | :--- |
| <a id="a-01"></a>入口は最新の年の机 | 入口は、**最新の年の机**。上に、「去年の今日」「今日の一枚」を置く                                                                                                  | 確定 |
| <a id="a-02"></a>年・月・できごと・すべてのズーム | ズーム(年 / 月 / できごと / すべて)を切り替えられる。時間の定規(つまみ)・パンくずで、行き来する。並び順は、**新しい順が既定**(古い順に切り替えられる)               | 確定 |
| <a id="a-03"></a>机の配置 | 「机」は、写真(ポラロイド)を、**格子の上に、傾けて置く**。重ならず、机の幅をはみ出さない。枚数が多い場合は、代表の枚数(既定 12)だけを置き、「もっと広げる」で増やす | 確定 |
| <a id="a-04"></a>できごとの自動まとめ | **できごと**を、撮影時刻の空きと場所から、自動でまとめる。年の机は月ごとの代表、月の机はできごとの束、できごとの机は写真を広げる                                    | 確定 |
| <a id="a-05"></a>マソンリーと行ぞろえ | ズーム「すべて」は、**マソンリー**(縦横の比率で、高さが違う列)を既定とし、**行ぞろえ**にも切り替えられる。いずれも、写真を切り抜かない                              | 確定 |
| <a id="a-06"></a>検索 | **検索**: 日付・カメラ・場所・ファイル名。入力中に候補を出し、決めた条件は札(チップ)になる                                                                          | 確定 |
| <a id="a-07"></a>絞り込み | **絞り込み**: 種別・カメラ・GPS・年・日付の精度・日付の取得元・ソース。条件ごとの件数を表示し、すべてのズームに効く                                                 | 確定 |

## 17. スコープ外(将来の拡張)

- 保存先にすでにある写真の台帳への登録(`index`)
- 見た目が似ている写真の重複検出
- 位置情報の推定
- 重複の「別物」判定と、それに伴う追加コピー(Web からファイルを書き込む操作)。重複は、一覧で確認するだけとする
- マイアルバム・お気に入り(自分で印を付ける機能。書き込みが要る)
- 背景地図のオフライン対応(必要になったら、追加を検討する)
- ファイルの削除(利用者が手動で行う)
