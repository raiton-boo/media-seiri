# 要件定義

状態の凡例: **確定** = ヒアリングで合意済み / **仮** = 暫定案(要確認) / **未決** = 要ヒアリング

## 1. 前提・制約

| ID   | 内容                                                                                                                                                                 | 状態 |
| :--- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :--- |
| C-01 | 写真・動画・台帳のデータは、外部へ送らない。処理はすべてローカルで行う。外部との通信は、背景地図のタイルの取得(C-11)だけに限る | 確定 |
| C-02 | 対象規模は 2TB 前後、1万枚以上。単発の大掃除が主用途                                                                                                                 | 確定 |
| C-03 | 整理はコピー専用とする。元データは変更・削除しない(バックアップ目的)。削除は利用者が手動で行う                                                                       | 確定 |
| C-04 | 整理(スキャンから取り込みまで)は CLI で行う。Web は、結果の閲覧専用とし、ファイルの書き込み・コピーの操作は持たない | 確定 |
| C-05 | 出力先は「ライブラリ」(§8)とし、外付け HDD に置く。ライブラリの中は、年・月のフォルダに分ける(`YYYY/MM/`)                                                            | 確定 |
| C-06 | 開発ルールは `docs/rules/` に従う                                                                                                                                    | 確定 |
| C-07 | 背景地図つきの地図表示を行う(取得方法は技術選定で決める)                                                                                                             | 確定 |
| C-08 | 整理(取り込み・修復・コピー)は、開発用のこの Mac だけで行う。家の PC(Windows など)では、保存済みのデータの**閲覧専用**で使う                                         | 確定 |
| C-09 | 出力先のドライブは、この Mac から読み書きできる形式(exFAT を推奨)でなければならない。NTFS(Mac では読み取り専用)や、4GB 超のファイルを置けない FAT32 には書き込まない | 確定 |
| C-10 | Docker は使わない(取り込みは Mac で直接動かし、ビューアは単体の実行ファイルで配布する) | 確定 |
| C-11 | 背景地図は、オンラインの地図タイルを取得して表示する(家の PC もネットワークにつながっている前提)。外部に送られるのは「見ている範囲のタイルの要求」だけで、写真・台帳のデータは送らない。タイルの提供元は、設定で変更できる。ネットにつながらない場合は、ピンと座標の一覧だけ使える | 確定 |

## 2. 対象ファイル

| ID   | 内容                                                                                                                                                                                                | 状態             |
| :--- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :--------------- |
| T-01 | 写真、動画、RAW 系ファイルを対象とする                                                                                                                                                              | 確定             |
| T-02 | 具体的な拡張子の一覧(写真 / 動画 / RAW)                                                                                                                                                             | 仮(仕様書で確定) |
| T-03 | ZIP 内のファイルも対象とする。ZIP は、ツールが1ファイルずつ一時領域に取り出して処理する(利用者が先に展開する必要はない)                                                                             | 確定             |
| T-04 | ZIP の入れ子(ZIP の中の ZIP)は深さ3まで開く。それ以上は警告して記録する。ZIP 内のフォルダの階層は、何層でもたどる                                                                                   | 確定             |
| T-05 | サイドカーの扱い。Google Takeout の `.json` は日時・GPS の取得元として読む(コピーはしない)。`.xmp` は RAW と同じ日時名で隣にコピーする。`.aae` / `.thm` / `.lrv` などは対象外にして件数だけ記録する。Takeout の json への対応は、実装の優先度が低い(今回の ZIP に Takeout はないため) | 確定             |
| T-06 | 写真・動画・RAW は同じ `YYYY/MM/` 階層に混在させる                                                                                                                                                  | 確定             |

| ID   | 内容                                                                                                                        | 状態 |
| :--- | :-------------------------------------------------------------------------------------------------------------------------- | :--- |
| I-01 | ソース(外付け・内蔵ストレージ)配下を再帰的にスキャンし、対象ファイルを検出する                                              | 確定 |
| I-02 | 各ファイルから撮影日時・GPS・カメラ情報などのメタデータを取得する                                                           | 確定 |

| I-04 | 同じ名前が既にある場合、内容が違えば連番(`_01`、`_02` …)を付けて追加コピーする                                              | 確定 |
| I-05 | RAW と JPEG の同名ペアは、同じ日時名で拡張子違いとして並べて保存し、重複扱いにしない                                        | 確定 |
| I-06 | 出力先の既存ファイルを上書きしない                                                                                          | 確定 |
| I-07 | 日付の一部しか取れなかった場合の置き場所と名前は、§4-2 の規則に従う                                                         | 確定 |
| I-08 | コピーしたファイルの更新日(mtime)は、元のものを引き継がない(コピーした時刻のままにする)                                     | 確定 |
| I-09 | 読み取れない・壊れていて修復もできないファイルは、`_unknown/読み取り不可/` へ、元の名前のままコピーする(バイトが読める限り) | 確定 |

## 4. 日付の決定と置き場所

### 4-1. 日付の決定

| ID   | 内容                                                                                                                                                                                                         | 状態             |
| :--- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :--------------- |
| D-01 | ファイル本体のメタデータの撮影日時を優先して使う                                                                                                                                                             | 確定             |
| D-02 | 本体のメタデータから取れない場合は、次の順に代替を試す: Takeout の `.json` → ファイル名の日付。**ファイルの更新日(mtime)は、日付として採用しない**(書き換わっていて信頼できないため)。参考情報として記録する | 確定             |
| D-03 | 本体のメタデータから取得できなかった時点で「日付フォールバック」とし、使った取得元の種別(json / ファイル名 / なし)と理由を一覧に記録する                                                                     | 確定             |
| D-04 | 優先順位の詳細(動画の UTC とローカル時刻、タイムゾーンの扱いを含む)                                                                                                                                          | 仮(仕様書で確定) |
| D-05 | 日付フォールバック一覧は、取得元の種別で絞り込める                                                                                                                                                           | 確定             |

### 4-2. 日付の精度による置き場所と名前

| ID   | 取れた日付の精度     | 置き場所                     | ファイル名                     | 状態 |
| :--- | :------------------- | :--------------------------- | :----------------------------- | :--- |
| U-01 | 年月日+時刻(すべて)  | `YYYY/MM/`                   | `YYYY.MM.DD_HH-MM-SS.<拡張子>` | 確定 |
| U-02 | 年月日のみ(時刻なし) | `YYYY/MM/_時刻不明/`         | `YYYY.MM.DD.<拡張子>`          | 確定 |
| U-03 | 年月のみ             | `YYYY/MM/_日付不明/`         | `YYYY.MM_<元の名前>.<拡張子>`  | 確定 |
| U-04 | 年のみ               | `YYYY/_月日不明/`            | `YYYY_<元の名前>.<拡張子>`     | 確定 |
| U-05 | 日付がまったくない   | `_unknown/日付なし/`         | `<元の名前>.<拡張子>`          | 確定 |
| U-06 | 日付の値が不正       | `_unknown/日付が不正/`       | `<元の名前>.<拡張子>`          | 確定 |
| U-07 | 修復後も日付がない   | `_unknown/修復後も日付なし/` | `<元の名前>.<拡張子>`          | 確定 |
| U-08 | 読み取り・修復が不可 | `_unknown/読み取り不可/`     | `<元の名前>.<拡張子>`          | 確定 |

- フォルダ名の先頭の `_` は、フォルダの並びで先頭に来るようにするため。
- 名前が衝突した場合は、いずれも連番(`_01` …)を付ける。
- 日付がどの精度で取れたかは、DB に記録し、Web の一覧で見られる。

## 5. ハッシュ・整合性

| ID   | 内容                                                                                               | 状態                 |
| :--- | :------------------------------------------------------------------------------------------------- | :------------------- |
| H-01 | コピー後にハッシュを照合し、転送中の破損を検出する                                                 | 確定                 |

| H-06 | ライブラリ全体のハッシュを計算し直して台帳と照合できる(`verify`)。ライブラリの移行後の確認にも使う | 確定                 |

## 8. ライブラリ・複数ソース・再実行

「ライブラリ」とは、整理済みの写真が入った1つのフォルダ(ライブラリの根)と、それを説明する台帳・サムネイルのひとまとまり。

| ID   | 内容                                                                                                                  | 状態 |
| :--- | :-------------------------------------------------------------------------------------------------------------------- | :--- |
| M-01 | 外付けごとに別々に実行できる                                                                                          | 確定 |
| M-02 | 以前の実行結果が、後の実行で失われたり上書きされたりしない                                                            | 確定 |
| M-03 | 実行ごとに ID を付け、どのソースから何をどうしたかを記録する                                                          | 確定 |
| M-04 | 同じソースを再実行しても、処理済みのファイルを二重にコピーしない                                                      | 仮   |
| M-05 | ライブラリの根に目印ファイルを置き、固有の ID で識別する(ドライブの名前では識別しない)                                | 確定 |
| M-06 | 台帳のパスは、ライブラリの根からの相対パスで記録する。ライブラリのフォルダごと別の HDD にコピーしても、そのまま使える | 確定 |
| M-07 | 取り込み中の作業用の台帳は、この Mac のプロジェクト配下(`data/`、git の管理対象外)に置く。保存場所は設定で変更できる  | 確定 |
| M-08 | 実行の最後に、台帳のコピー(スナップショット)を、ライブラリの中に保存する                                              | 確定 |
| M-09 | ライブラリが複数ある場合、それぞれの台帳は独立している(ライブラリ間の重複は検出しない)                                | 確定 |
| M-10 | 保存先のライブラリにすでにある写真の登録(`index`)は、今回は対象外とする(空のドライブから始める)                       | 確定 |

## 17. スコープ外(将来の拡張)

- 保存先にすでにある写真の台帳への登録(`index`)
- 見た目が似ている写真の重複検出
- 位置情報の推定
- 重複の「別物」判定と、それに伴う追加コピー(Web からファイルを書き込む操作)。重複は、一覧で確認するだけとする
- 背景地図のオフライン対応(必要になったら、追加を検討する)
- ファイルの削除(利用者が手動で行う)
