# ブランチ戦略 (Branching Strategy)

## 要点

- `main` へ直接pushしない。必ずPRを経由してマージする。
- 作業ブランチ名は `接頭辞/短い英単語（ケバブケース）` にする（例: `feat/login-page`）。
- マージ後は作業ブランチを削除する。

---

## 運用フロー

### main ブランチ

常にデプロイ可能な本番環境の状態を保つ。

- 直接の `push` は禁止。必ずPR（Pull Request）を経由してマージする。
- 例外: プロジェクトの初期セットアップ時（最初のコミット、フレームワークの初期生成、`.gitignore` の追加など）は、PRを通さず直接 `main` にpushしてよい。

### dev ブランチ

開発段階・ステージング用。原則として使わない。ステージング環境が必要な場合など、やむを得ない場合のみ使用する。

### 作業ブランチ

開発を行う際は、`main`（または `dev`）、もしくは他の作業ブランチから新しい作業用ブランチを切る。

- 他の作業ブランチから切った場合は、PRのベースを切り元の作業ブランチにする。
- 大きな変更を分けたい場合は、[親ブランチ方式](./PR.md#5-親ブランチ方式)か[スタックPR](./PR.md#6-スタックprgh-stack方式)を使う。使い分けは [PR.md](./PR.md#4-大きな変更を分けて出す方法適材適所) を参照。

---

## ブランチの削除

マージ後は作業ブランチを削除する。

- **リモート**: GitHubの「Automatically delete head branches」設定で自動削除する。
- **ローカル**: 次の優先順位で削除する。
  1. `gh poi`（マージ済みのブランチをまとめて削除する `gh` の拡張機能）
  2. `gbclean`（自前aliasのブランチ削除コマンド）
  3. `git branch -d <ブランチ名>`
- **削除してはいけないブランチ**: 他のPRのベースになっているブランチは、そのPRがマージされるまで削除しない。
- **未マージのブランチ**: 削除は破壊的操作に当たるため、事前に内容を確認する（[AI-GUIDELINES.md](./AI-GUIDELINES.md) 参照）。

---

## ブランチの命名規則

ブランチ名は `接頭辞/短い英単語（ケバブケース）` のフォーマットとする。
内容はひと目で分かる、なるべく簡潔な単語を選択すること。

| OK                   | NG                                 | 理由                              |
| :------------------- | :--------------------------------- | :-------------------------------- |
| `feat/login-page`    | `feat/add-new-login-page-for-user` | 長すぎる                          |
| `fix/header-bug`     | `fix_header_bug`                   | 接頭辞と名前の区切りが `/` でない |
| `fix/login-error`    | `fix/LoginError`                   | ケバブケースでない                |
| `feat/add-user-auth` | `login`                            | 接頭辞がない                      |

---

## 接頭辞（プレフィックス）の種類

コミットメッセージの規約と統一し、以下のプレフィックスを使用する。

| 接頭辞          | 用途                                                                           | 具体例                  |
| :-------------- | :----------------------------------------------------------------------------- | :---------------------- |
| **`feat/`**     | 新機能の追加                                                                   | `feat/add-user-auth`    |
| **`fix/`**      | バグの修正                                                                     | `fix/login-error`       |
| **`hotfix/`**   | 本番環境（`main`）の緊急バグ修正（[手順](./PR.md#7-hotfix本番の緊急バグ修正)） | `hotfix/payment-crash`  |
| **`refactor/`** | リファクタリング（機能追加やバグ修正を含まない）                               | `refactor/user-service` |
| **`chore/`**    | パッケージ追加、ビルドプロセスの変更など雑務                                   | `chore/update-deps`     |
| **`docs/`**     | ドキュメント（README等）の追加・修正                                           | `docs/update-readme`    |
| **`test/`**     | テストコードの追加・修正                                                       | `test/auth-logic`       |
| **`ci/`**       | CI/CD（GitHub Actions等）の設定変更                                            | `ci/deploy-workflow`    |

---

## Gitコマンドの使い分け

役割の混同を防ぐため、`git checkout` は使わない。

- ブランチの切り替え: `git switch`
- ファイルの復元・取り消し: `git restore`
