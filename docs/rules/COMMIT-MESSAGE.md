# コミットメッセージ規約 (Commit Message Conventions)

履歴の可読性を高めるため、1行で完結するプレフィックス型のメッセージを採用する。

## 要点

- 形式は `<type>: <subject>` の1行。コロンの後ろに半角スペースを1つ入れる。
- `type` はブランチの接頭辞と同じものを使う（`feat`, `fix` など）。
- 1コミット＝1つの関心事。背景や詳細はPRの本文に書く。

---

## 1. 基本フォーマット

    <type>: <subject>

- `type`: コミットの種類（ブランチの接頭辞と完全に一致させる）
- `subject`: 変更内容の簡潔な要約

| OK                              | NG                            | 理由                             |
| :------------------------------ | :---------------------------- | :------------------------------- |
| `feat: ユーザー認証機能を追加`  | `feat:ユーザー認証機能を追加` | コロンの後ろに半角スペースがない |
| `fix: ヘッダーの崩れを修正`     | `修正: ヘッダー`              | `type` が規約外                  |
| `fix: ログイン時のエラーを修正` | `fix: いろいろ修正`           | 何を変えたかが分からない         |

---

## 2. プレフィックス (Type) 一覧

| Type            | 用途                                       | コミットメッセージの例                       |
| :-------------- | :----------------------------------------- | :------------------------------------------- |
| **`feat:`**     | 新機能の追加                               | `feat: ユーザー認証機能を追加`               |
| **`fix:`**      | バグ修正                                   | `fix: スマホ画面のレイアウト崩れを修正`      |
| **`hotfix:`**   | 本番の緊急バグ修正                         | `hotfix: 決済APIのエラーを修正`              |
| **`refactor:`** | リファクタリング（機能追加やバグ修正なし） | `refactor: ログインロジックの共通化`         |
| **`chore:`**    | ツール設定、パッケージ更新、雑務           | `chore: 依存パッケージのアップデート`        |
| **`docs:`**     | ドキュメントの追加・修正                   | `docs: READMEにセットアップ手順を追記`       |
| **`test:`**     | テストの追加・修正                         | `test: ログインバリデーションのテストを追加` |
| **`ci:`**       | CI/CD（GitHub Actions等）の変更            | `ci: 本番デプロイ用のワークフローを追加`     |

---

## 3. ベストプラクティス

- **1コミット＝1つの関心事**: 新機能（`feat`）とリファクタリング（`refactor`）など、複数の関心事を1つのコミットに混ぜない。
- **基本は1行で完結させる**: 背景や詳細な理由はPRの概要欄に記載する。
