# 📌 Issue運用規約 (Issue Guidelines)

本規約は、タスクの目的・内容および完了基準を明確にし、開発の進捗管理とPR（プルリクエスト）との連携をスムーズにすることを目的とする。

## 1. Issue作成の基本ルール

- **タイトル命名規則**
  - タイトルの先頭には、変更内容がひと目でわかるプレフィックスを角括弧 `[ ]` で付与する。
  - フォーマット: `[接頭辞]: 簡潔なタスク名`
  - 例: `[feat]: ログイン画面のUI実装`, `[fix]: ヘッダーの崩れを修正`
- **1 Issue ＝ 1 タスク**
  - 1つのIssueに複数の目的を詰め込まない。作業が多岐にわたる場合は、タスクを分割して別Issueにする。
- **ブランチ作成との紐付け**
  - 作業を始める際は、原則として対応するIssueを作成してからブランチを切り出す。
- **ブランチ命名へのIssue番号含め**
  - ブランチ戦略に従い、切り出すブランチ名には該当するIssue番号を含める（例: `feat/#12-login-page`）。

---

## 2. Issueのテンプレート

Issueを作成する際は、以下の基本フォーマット（`.github/ISSUE_TEMPLATE/` に設定推奨）を使用する。

```markdown
## 概要・目的

<!-- 何を、なぜ実装/変更するのか -->

## やること

- [ ] 〇〇のUI実装
- [ ] APIのレスポンス処理を追加

## 受け入れ条件

- 〇〇ボタンを押すと正常にログイン処理が行われること
- エラー時に適切なエラーメッセージが表示されること

## 備考・補足（あれば）

<!-- 参考資料、デザイン案のリンク、関連するコードなど -->
```

## 3. ラベル (Labels) の運用方法（任意）

ラベルはIssueの分類や整理を補助するためのものです。**設定は必須ではありません**が、状況や必要に応じて適宜付与してください。

### 3-1. 種別ラベルの例

| ラベル名   | 用途・意味                                 |
| :--------- | :----------------------------------------- |
| `feature`  | 新機能の追加・仕様変更                     |
| `fix`      | バグ・不具合の修正                         |
| `refactor` | 機能追加・バグ修正を伴わないコードの整理   |
| `docs`     | ドキュメントの追加・修正                   |
| `chore`    | ビルド設定やライブラリ更新などその他の作業 |

### 3-2. 優先度・緊急度ラベルの例

本番環境の不具合など、緊急性が高いタスクを区別したい場合に活用できます。

| ラベル名         | 用途・意味                                       |
| :--------------- | :----------------------------------------------- |
| `hotfix`         | 本番障害など、最優先で即時対応が必要な緊急タスク |
| `priority: high` | 優先度【高】：早めに対応したい重要タスク         |
| `priority: low`  | 優先度【低】：時間に余裕がある時に対応するタスク |

---

## 4. クローズ（完了）の自動化

PR作成時、概要欄に `Closes #Issue番号` （例: `Closes #12`）と記載することで、PRマージ時に該当のIssueが自動的にクローズされるようにする。
