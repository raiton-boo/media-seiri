# Issue運用規約 (Issue Guidelines)

本規約は、タスクの目的・内容および完了基準を明確にし、開発の進捗管理とPR（プルリクエスト）との連携をスムーズにすることを目的とする。

## 要点

- タイトルは、日本語で「やりたいこと」が分かるように書く。種類が明確なときだけ、先頭に `接頭辞: ` を付ける。
- 1 Issue＝1タスク。作業が多岐にわたるときは、Issueを分ける。
- 作業は、Issueを作成してからブランチを切って始める。
- `main` にマージするPRの本文に `Closes #Issue番号` を書き、Issueを自動クローズする（[PR.md](./PR.md#関連issueの書き方) 参照）。

---

## 1. Issue作成の基本ルール

- **タイトル**: 日本語で、やりたいことが分かるように書く。変更の種類が1つに決まり、明確なときだけ、先頭に `接頭辞: ` を付ける。迷うときは付けない。
  - 接頭辞は、種類を示すために使う。`chore: 作業タスク` のように、内容を表さない書き方はしない。
  - 接頭辞の種類は、コミット・ブランチと同じ（`feat` `fix` `hotfix` `refactor` `chore` `docs` `test` `ci`）。
- **1 Issue＝1タスク**: 1つのIssueに複数の目的を詰め込まない。作業が多岐にわたる場合は、タスクを分割して別Issueにする。
- **ブランチとの紐付け**: 作業を始める際は、原則として対応するIssueを作成してからブランチを切り出す。ブランチ名は [BRANCHING.md](./BRANCHING.md) に従い、IssueとブランチはPR本文の `Closes #Issue番号` で紐付ける。

| OK                           | NG                         | 理由                       |
| :--------------------------- | :------------------------- | :------------------------- |
| `ヘッダーの崩れを直す`       | `fix:ヘッダーの崩れを修正` | `:` と半角スペースがない   |
| `feat: ログイン画面のUI実装` | `chore: 作業タスク`        | 内容が分からない           |
| `依存パッケージを更新する`   | `ログインとUIの修正`       | 複数のタスクが混ざっている |

---

## 2. Issueのテンプレート

Issueを作成する際は、以下の汎用テンプレート（`.github/ISSUE_TEMPLATE/` に設定推奨）を使用する。機能追加、バグ修正、作業タスクのどれでも、同じテンプレートで書く。

```markdown
## 概要

<!-- 何を、なぜ。バグの場合は、再現手順・期待する動作・実際の動作も書く -->

## 完了条件

-

## 補足（あれば）

<!-- 参考資料、エラーログ（機密情報は除く）など -->
<!-- 関連Issue: #xx -->
```

## 3. ラベル (Labels) の運用方法（任意）

ラベルはIssueの分類や整理を補助するためのもので、**設定は必須ではない**。状況や必要に応じて付与する。

名前は、軸ごとに接頭辞を付けてそろえる。

| 軸       | ラベル                                                                                                      | 用途                                                                         |
| :------- | :---------------------------------------------------------------------------------------------------------- | :--------------------------------------------------------------------------- |
| 種別     | `type: feat` `type: fix` `type: hotfix` `type: refactor` `type: chore` `type: docs` `type: test` `type: ci` | 変更の種類。種類が明確なときだけ付け、タイトルの接頭辞と一致させる           |
| 優先度   | `priority: high` `priority: low`                                                                            | 早めに対応したいもの、余裕のあるときに対応するもの。付けなければ通常の優先度 |
| 状態     | `status: blocked` `status: needs-info`                                                                      | 他の作業や判断待ちで進められない、情報不足で着手できない                     |
| 対象範囲 | `area: <領域名>`（例: `area: auth`）                                                                        | 機能の領域で絞り込む。領域名はプロジェクトごとに決める                       |
| 解決     | `duplicate` `wontfix`                                                                                       | 重複、対応しないIssueを閉じるときに付ける（GitHubの標準ラベル名のまま使う）  |

- `type: hotfix` は、本番環境の緊急バグ修正に使う。緊急の場合は、`priority: high` も付ける。

---

## 4. クローズ（完了）

Issueは、PRのマージ時に自動でクローズされる。書き方は [PR.md](./PR.md#関連issueの書き方) を参照。
