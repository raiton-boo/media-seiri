# 🤖 AI・コーディングアシスタント規約 (AI Coding Guidelines)

本規約は、AIアシスタント（Cursor, Claude Code, GitHub Copilot等）を効果的かつ安全に活用し、意図しない事故を防ぎながら開発効率を向上させることを目的とする。

## 1. 基本方針・責任範囲

- **最終責任は人間（開発者）にある**
  - AIが生成・編集したコードやコマンドは、必ず人間が内容を検証した上で適用およびコミットを行う。
- **ワンショットでの大規模変更の禁止**
  - AIに一度で大量のファイルを変更させず、小さな単位で段階的に生成・検証を行う。
- **設計意図・方針の事前説明（必至）**
  - AIはコードの生成や大幅な編集を行う前に、**必ず提案する実装方針や設計意図を一度人間に説明・確認した上で**コードを出力すること。

---

## 2. 権限・操作ルール（重要）

AIアシスタントに付与する権限は「調査・確認」と「編集・実行」で厳格に区別する。

### 2-1. 【事前承認が必要】ソースコードの編集・書き込み・各種実行コマンド

以下の操作は、**人間（開発者）から明示的に依頼された場合のみ**許可する。依頼されていないタイミングでの自主的な編集・実行は厳禁とする。

- **ソースファイルの編集・書き込み (Write / Edit)**
  - 例: 「〇〇機能を代わりに実装して」「このバグを修正して」と指示された場合のみ、対象範囲の編集を許可。
- **状態を変更するコマンドの実行**
  - Git操作（`git commit`, `git push` 等）、GitHub CLI（`gh pr create` 等）、パッケージ追加・更新、各種デプロイや設定変更コマンドなど。
- **🚨【安全装置】破壊的変更の絶対的な禁止と事前確認**
  - 以下の「破壊的変更」を行う可能性がある場合、**たとえ人間から依頼された操作であっても、影響範囲を提示し必ず人間の明示的な再確認を得てから実行・編集すること**。
    - 既存機能の削除、大幅なリファクタリング、スキーマや構造の非互換な変更
    - ファイルやディレクトリの削除・移動
    - 破壊的なコマンドの実行（`git reset --hard`, `git push --force`, DBドロップ等）

### 2-2. 【無承認で許可】調査・分析・デバッグのための操作

プロジェクトの構造把握や原因究明をスムーズに行うため、以下の操作は**人間の事前承認なしで自由に実行・参照してよい**。

- **読み取り専用のアクセス (Read-only)**
  - ディレクトリ構造の確認、ファイル・フォルダの読み込み、設定の参照、コードの静的解析など。
- **調査・確認目的のコマンド実行**
  - ログの出力確認、エラー調査、ビルドやテストの事前確認など。
- **一時的なデバッグコードの挿入**
  - 原因調査のためにログ出力用コード等を一時的に書き込むことは許可する。**ただし、調査完了後は必ず元通りに削除（クリーンアップ）すること**。

---

## 3. セキュリティと機密情報

- **機密情報の入力禁止**
  - APIキー、パスワード、DB接続情報などの各種クレデンシャルは、絶対にプロンプトやチャットツールに入力しない。
- **個人情報・環境情報の保護**
  - 実際のユーザーデータや機密性の高い情報は含めず、必要に応じてダミーデータに置き換えて質問する。

---

## 4. クリンリネスと品質管理

- **既存ルールの遵守**
  - プロジェクト内のブランチ戦略、コミット規約、コーディング規約（Linter/Formatter等）に従った挙動を維持させる。
- **不要なコードの削除**
  - AIが生成した不要なコメントや、デバッグ用のコード（`console.log`, `print` 等）はPR提出前にすべて削除する。
